## 1. نظرة عامة وهيكل المشروع

يعتمد هذا النظام على بوابة دخول خفيفة وسريعة مصممة خصيصاً لتعمل مباشرة على خادم الويب المدمج في راوترات ميكروتك (RouterOS HTTP Web Server) أو عبر خوادم Node.js/Express وسيطة. يتميز النظام بالقدرة على إتاحة اختيار سرعات البث للمستخدم مباشرة من المتصفح دون الحاجة لتغيير كرت الشبكة، وحفظ بيانات الكروت في كوكيز المتصفح، وإدارة قيود الأجهزة.

## 2. خريطة دورة حياة الاتصال والارتباط بالمايكروتك (Lifecycle Map)

```text
[اتصال الهاتف بشبكة الواي فاي]
           │
           ▼
[إرسال استعلام نظام التشغيل: Android / iOS / Windows Probe]
           │
           ├─► استجابة المايكروتك عبر rlogin.html و redirect.html
           │
           ▼
[فتح متصفح النظام المنبثق Captive Portal تلقائياً]
           │
           ▼
[تحميل login.html] ──── (فحص الكوكيز hotCookie.min.js)
           │                        │
           │           يوجد كرت مخزن بدون خطأ سابق؟
           │           ├─ نعم ──► تسجيل دخول فوري GET /login?username=...
           │           └─ لا
           ▼
[إدخال كرت المستخدم + اختيار السرعة]
           │
           ├─► hotInImprover: تنظيف الفراغات وتحويل ٠١٢٣٤٥ إلى 012345
           ├─► دالة rem(): حفظ الكوكيز (uname + password)
           │
           ▼
[إرسال النموذج POST أو CHAP إلى $(link-login-only)]
           │
      ┌────┴────────────────────────┐
      ▼                             ▼
[فشل المصادقة]                [نجاح المصادقة]
      │                             │
تخزين error=1 بالكوكيز لمدة 5ث     تخزين جلسة المايكروتك
إعادة التوجيه لـ login.html         تحويل إلى alogin.html
عرض نص الخطأ بالعربية المترجمة      ثم التحويل الفوري لـ status.html
                                    │
                                    ▼
                         [عرض تفاصيل الحساب الحية]
                         - استهلاك الجلسة / الرصيد
                         - الوقت المتبقي
                         - فك شفرة السرعة والخدمات
```

## 3. نظام السرعات والخدمات وسلسلة الدومين (Speed & Domain Architecture)

السر الجوهري في هذه البوابة هو دمج السرعات والخصائص المتقدمة داخل اسم المستخدم نفسه عبر إضافة لاحقة (Suffix) نصية، بحيث يتعرف المايكروتك على ملف السرعة (User Profile) وجدار الحماية (Firewall Mangle) بناءً على ما بعد رمز `@` أو شفرة الخيارات.

### تركيبة سلسلة القيمة المتعددة:
```text
اسم_المستخدم + @السرعة | المستخدمين | VPN | التصفح | التحديثات | الماك
مثال:
123456@512K/1M|0|pm|all|*no**|non***
```

### تفكيك مكونات السلسلة:
| الحقل | الرمز | المعنى الفني في النظام | التأثير في المايكروتك |
| :--- | :--- | :--- | :--- |
| **السرعة** | `@256K/256K` | سرعة اقتصادية | تحديد Rate-Limit بـ 256 كيلوبت رفع وتنزيل |
| | `@256K/512K` | سرعة عادية | تحديد Rate-Limit بـ 256K رفع و 512K تنزيل |
| | `@512K/1M` | سرعة متوسطة | تحديد Rate-Limit بـ 512K رفع و 1M تنزيل |
| | `@1M/4M` | سرعة عالية | تحديد Rate-Limit بـ 1M رفع و 4M تنزيل |
| | `@1M/8M` | سرعة عالية جداً | أقصى سعة تحميل للكرت |
| **المستخدمين** | `0` | الافتراضي | السماح بعدد الجلسات المشتركة المحدد بالبروفايل |
| **خدمة VPN** | `pm` | بدون VPN | حركة مرور طبيعية بدون حزم VPN إضافية |
| | `pu` | مخصص للألعاب (ببجي) | توجيه الترافيك لسيرفرات الألعاب بأولوية PING منخفض |
| **التصفح** | `all` | كل المواقع | فتح الوصول لجميع الوجهات عبر الويب |
| | `whats` | واتساب فقط | حظر المواقع الأخرى وتمرير نطاقات واتساب |
| | `face` | فيسبوك فقط | حظر المواقع الأخرى وتمرير نطاقات فيسبوك |
| **التحديثات** | `*yes**` | إيقاف التحديثات | حظر خوادم Windows Update و Play Store لحفظ الرصيد |
| | `*no**` | سماح بالتحديثات | فتح مسار خوادم التحديثات دون قيود |
| **الماك** | `non***` | الافتراضي | ربط عادي للماك |
| | `no***` | غير مفعل | عدم تقييد الكرت بجهاز واحد |
| | `yes***` | مفعل | قفل الكرت على عنوان MAC للجهاز الحالي |

### محرك فك التشفير في `status.html`:
دالة `hamza()` تستقبل قيمة متغير المايكروتك `$(domain)` وتفككها عبر أمر `split('|')`:
- تقرأ السرعة والخدمات وتضعها في عناصر الجدول المعروضة أمام المستخدم:
  - `#spee`: يعرض السرعة الحالية للمستخدم.
  - `#shared`: يعرض حالة اشتراك الكرت.
  - `#web`: يعرض نوع التصفح المحدد.
  - `#vbn`: يعرض وضع الـ VPN.
  - `#update`: يعرض إذا كانت التحديثات مفعلة أم متوقفة.
  - `#mac`: يعرض حالة الربط بالماك.

### دورة تعديل الخدمة الفورية (تطبيق الخدمات):
1. يغير المستخدم الخيار من أي قائمة منسدلة في صفحة الحالة.
2. تستدعي القوائم دالة `rem()` المشفرة التي تعيد تجميع السلسلة الجديدة وتخزنها في الكوكيز.
3. يضغط المستخدم زر **"تطبيق الخدمات"** (`myFunction()`).
4. يغير الزر نصه إلى `"الرجاء الانتظار سيتم تطبيق الخدمات فورا"`.
5. يرسل النموذج أمر إنهاء الجلسة `$(link-logout)` مع معلمة `erase-cookie=on`.
6. يخرج المايكروتك المستخدم ويعود به إلى `login.html`.
7. يقرأ سكربت `hotCookie.min.js` الكوكيز الجديدة المعدلة ويسجل دخوله تلقائياً فوراً بالسرعة والخدمة الجديدة!

## 4. نظام الكوكيز والتسجيل التلقائي وحماية الحلقات (Cookies & Auto-Login)

ملف `js/hotCookie.min.js` مسؤول عن استمرارية تسجيل الدخول وحماية المستخدم:

### 1. الكوكيز المخزنة:
- **`uname`**: يخزن اسم المستخدم شاملاً لاحقة السرعة، مدة صلاحيته **259,200 ثانية (3 أيام كاملة)**.
- **`paswd`**: يخزن كلمة المرور (في حال وجودها)، مدة صلاحيته **3 أيام**.
- **`error=1`**: كوكي أمان مؤقت ينشأ لمدة **5 ثوانٍ فقط**.

### 2. آلية منع حلقة إعادة التوجيه اللانهائية (Loop Prevention):
- عند الدخول لصفحة الدخول، تفحص دالة `getCookie()` ما إذا كان هناك كوكي باسم `error`.
- **إذا كان موجوداً**: يعني ذلك أن المستخدم حاول الاتصال وفشل منذ لحظات، فيتوقف السكربت عن التسجيل التلقائي لمنع المتصفح من محاولة الدخول المتكرر التي تتسبب في حظر الماك أو تعليق الهاتف.
- **إذا لم يكن موجوداً**: يستخرج السكربت الكرت من الكوكي ويطلب فورا:
  ```javascript
  window.location.href = 'login?username=' + uname + '&password=' + paswd;
  ```

### 3. زر "تسجيل بكرت آخر":
- تم تزويد صفحة الحالة بزر مخصص **"تسجيل بكرت آخر"** يستدعي دالة `delrem()`:
  ```javascript
  document.cookie = "uname=; expires=Thu, 01 Jan 1970 00:00:00 UTC; path=/;";
  ```
- هذا الإجراء يمسح الكرت القديم بالكامل من ذاكرة الهاتف فوراً، مما يسمح للمستخدم بكتابة كرت جديد عند فتح صفحة الدخول دون أن يسجل الهاتف بالكرت القديم رغماً عنه.

## 5. التوافقية مع الهواتف الذكية وتصحيح المدخلات (Device Compatibility & hotInImprover)

أحد أهم التحديات في شبكات المايكروتك في الوطن العربي هو وقوع أخطاء إدخال من كيبورد الهواتف الذكية تؤدي لرفض الكروت الصالحة. تم حل هذه المشكلة بالكامل عبر ملف `js/hotInImprover.min.js`:

### 1. تحويل الأرقام العربية إلى إنجليزية تلقائياً:
- تستخدم الهواتف (خاصة iPhone عند اختيار لوحة مفاتيح عربية) الأرقام الهندية المشرقية (`٠١٢٣٤٥٦٧٨٩`). راوتر ميكروتك يرفض هذه الأرقام ويعتبرها رموزاً غير صالحة.
- يقوم السكربت بتحويل الحروف تلقائياً بمجرد الكتابة أو اللصق:
  - الرمز `1632` (`٠`) يتحول إلى `0`
  - الرمز `1633` (`١`) يتحول إلى `1`
  - الرمز `1634` (`٢`) يتحول إلى `2`
  - الرمز `1635` (`٣`) يتحول إلى `3`
  - الرمز `1636` (`٤`) يتحول إلى `4`
  - الرمز `1637` (`٥`) يتحول إلى `5`
  - الرمز `1638` (`٦`) يتحول إلى `6`
  - الرمز `1639` (`٧`) يتحول إلى `7`
  - الرمز `1640` (`٨`) يتحول إلى `8`
  - الرمز `1641` (`٩`) يتحول إلى `9`

### 2. إزالة المسافات الفارغة (rm-white-spaces):
- عند نسخ كود الكرت من محادثة واتساب أو رسالة SMS، ينسخ الهاتف غالباً مسافة في البداية أو النهاية.
- السكربت يزيل جميع المسافات (`value.split(" ").join("")`) على الفور.

### 3. توافقية متصفحات الأنظمة (Captive Portal Browsers):
- **Apple iOS (CNA)**: توافق تام عبر صفحة `redirect.html` وخفة حجم أكواد الـ CSS لتفادي إغلاق نافذة المصادقة التلقائية لـ Apple.
- **Android CaptivePortalLogin**: دعم كامل لجميع نسخ أندرويد من 5.0 حتى أحدث إصدارات Android 15.
- **Huawei & Honor (EMUI / HarmonyOS)**: التوافق مع محركات WebKit المدمجة.
- **Windows / Mac OS**: استجابة فورية ونظام عرض ريسبونسيف كامل يملأ الشاشة بسلاسة.

## 6. قاموس رسائل الخطأ والتنبيهات في المايكروتك (Error Translation Engine)

يقوم راوتر ميكروتك بتمرير سبب فشل الاتصال باللغة الإنجليزية في متغير `$(error)`. يتضمن ملف `login.html` محرك ترجمة فوري يعرض للمستخدم رسائل عربية واضحة ومباشرة:

| نص رسالة المايكروتك الإنجليزية `$(error)` | الرسالة العربية المعروضة للمستخدم | سبب المشكلة وكيفية معالجتها |
| :--- | :--- | :--- |
| `simultaneous session limit reached` | **الكرت مستخدم في جهاز آخر** | عدد الأجهزة المتصلة بالكرت وصل للحد الأقصى (Shared Users). |
| `invalid password` | **كلمة المرور غير صحيحة** | الرمز السري للكرت غير مطابق لما هو مسجل في المايكروتك. |
| `no valid profile found` | **انتهت صلاحية الرصيد** | كرت المستخدم انتهت فترة صلاحيته الزمنية (Validity). |
| `user <name> not found` | **المستخدم غير موجود** | رقم الكرت غير مسجل في اليوزر مانجر أو قائمة المستخدمين. |
| `no more sessions are allowed for user` | **الكرت مستخدم في جهاز آخر** | تجاوز حد الجلسات المتزامنة المسموح بها. |
| `uptime limit reached` | **انتهى رصيد هذا الكرت** | نفاد الوقت المخصص للكرت (مثال: ساعتين أو 24 ساعة). |
| `download limit reached` | **انتهى رصيد هذا الكرت** | نفاد كمية تحميل البيانات (مثال: 1 جيجابايت). |
| `transfer limit reached` | **لقد استغرغت كامل رصيد الانترنت الخاص بهذا الكرت** | نفاد إجمالي الرفع والتنزيل للكرت. |
| `invalid Calling-Station-Id` | **لا يمكنك استخدام هذا الرقم، لأنه تم تخصيصه لجهاز آخر** | الكرت مقيد بماك أدرس جهاز محدد ومحاولة الدخول تمت من جهاز مختلف. |
| `web browser did not send challenge response` | **أعد المحاولة مرة أخرى، إذا ظهرت هذه الرسالة مجدداً فيجب تفعيل الجافا سكربت في متصفحك** | المتصفح لا يدعم أو يعطل تشغيل الجافاسكربت الخاص بحساب تشفير CHAP. |

## 7. آليات المصادقة المزدوجة (HTTP PAP vs HTTP CHAP vs GET)

تدعم البوابة كل أساليب المصادقة القياسية في بروتوكول MikroTik Hotspot:

### 1. نمط HTTP PAP (النص الصريح):
- يعمل عبر نموذج الفورم التقليدي:
  ```html
  <form name="login" action="$(link-login-only)" method="post">
    <input type="text" name="username">
    <input type="password" name="password">
  </form>
  ```
- هذا النمط هو الأسرع والأكثر توافقية مع كافة أنواع الأجهزة الذكية والرخيصة.

### 2. نمط HTTP CHAP (التحدي المشفر بـ MD5):
- إذا كان خيار CHAP مفعلاً في المايكروتك، يولد الراوتر وسماً شرطياً:
  ```html
  $(if chap-id)
  <form name="sendin" action="$(link-login-only)" method="post">
      <input type="hidden" name="username" />
      <input type="hidden" name="password" />
      <input type="hidden" name="dst" value="$(link-orig)" />
  </form>
  <script type="text/javascript">
      function doLogin() {
          document.sendin.username.value = document.login.username.value + document.login.speed.value;
          document.sendin.password.value = document.login.password.value;
          document.sendin.submit();
          return false;
      }
  </script>
  $(endif)
  ```
- يقوم السكربت بدمج السرعة مع الكرت وإرسال الاستجابة المشفرة دون تعريض كرت المستخدم للتنصت عبر الشبكة.

### 3. نمط الـ GET المباشر:
- الرابط: `http://10.0.0.1/login?username=USER&password=PASS`
- يدعمه المايكروتك افتراضياً ويستخدمه سكربت `hotCookie.min.js` لإجراء الدخول التلقائي في الخلفية بسرعة البرق.

## 8. شاشات الإعلانات والتحويل وWISPr (radvert, redirect, rlogin, alogin)

### 1. `rlogin.html` (معيار WISPr):
- يحتوي على كود XML مطابق لمواصفات تحالف اللاسلكي عريض النطاق (Wireless Broadband Alliance):
  ```xml
  <WISPAccessGatewayParam xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance">
    <Redirect>
      <AccessProcedure>1.0</AccessProcedure>
      <LoginURL>$(link-login-only)?target=xml</LoginURL>
      <MessageType>100</MessageType>
      <ResponseCode>0</ResponseCode>
    </Redirect>
  </WISPAccessGatewayParam>
  ```
- هذا الملف هو المسؤول عن ظهور علامة التعجب على شبكة الواي فاي في شريط الإشعارات وظهور رسالة **"تسجيل الدخول إلى الشبكة"** فور الاتصال.

### 2. `redirect.html`:
- يقوم بعمل تحويل لحظي برمز HTTP 302 إلى الوجهة الأصلية `$(link-redirect)` فور المصادقة لضمان فتح صفحة الإنترنت التي كان يحاول المشترك زيارتها قبل ظهور البوابة.

### 3. `alogin.html`:
- يفتح نافذة الحالة `status.html` إذا كان خيار الـ Popup مفعلاً في السيرفر بروفايل، ثم يحول المتصفح الأساسي للإنترنت.

### 4. `radvert.html`:
- يُستخدم في حال تفعيل ميزة الإعلانات الدورية (Advertise) في راوتر المايكروتك لعرض بنرات تجارية أو تنبيهات إدارية كل فترة زمنية محددة.

## 9. إعدادات راوتر بورد ميكروتك الموصى بها (RouterOS Configurations)

لضمان عمل كافة ميزات البوابة (بما فيها السرعات، الكوكيز، والتشفير) بدون أي تعارض، اتبع الإعدادات التالية في **Winbox**:

### 1. إعدادات Hotspot Server Profile:
```routeros
/ip hotspot profile
set [ find default=yes ] \
    hotspot-address=10.0.0.1 \
    html-directory=hotspot \
    http-cookie-lifetime=3d \
    login-by=cookie,http-chap,http-pap \
    split-user-domain=no \
    use-radius=no
```
> **تنبيه حاسم:** يجب التأكد من ضبط `split-user-domain=no` حتى لا يقوم المايكروتك بفصل ما بعد علامة `@` واعتبارها اسم نطاق منفصل، بل يتم تمرير السلسلة بالكامل إلى اليوزر مانجر أو قواعد البروفايلات.

### 2. إعدادات مطابقة السرعات في User Profiles:
قم بإنشاء بروفايلات مطابقة للاختيارات الموجودة في البوابة:
- بروفايل باسم أو Rate Limit بـ `256k/256k`
- بروفايل بـ `256k/512k`
- بروفايل بـ `512k/1M`
- بروفايل بـ `1M/4M`
- بروفايل بـ `1M/8M`

## 10. دليل الصيانة وتفادي الأعطال الحساسة (Troubleshooting & Critical Warnings)

### ⚠️ تحذيرات برمجية هامة جداً:
1. **لا تقم بتعديل أسماء المعرفات (IDs) في ملفات HTML:**
   - الحقول: `uname`, `paswd`, `speed`, `speedd`, `speeddd`, `speedddd`, `speeddddd`, `speedddddd` مرتبطة بروابط برمجية مصفوفية مدمجة داخل الأكواد المشفرة `_0x1383` و `hamza()`. أي تعديل في أي `id` سيعطل حساب الخدمات وتطبيقها بالكامل.
2. **عدم مسح سطر الفحص السريع للأخطاء بالكوكيز:**
   - دالة `getCookie()` تفحص وجود كوكي `error`. إزالته ستسبب حلقة إعادة توجيه لا نهائية تعطل هواتف المشتركين إذا كان الكرت منتهياً.
3. **أبعاد الصور في مجلد `img/`:**
   - صور السلايدر (`pic1.jpg` إلى `pic4.jpg`) يجب ألا تتجاوز أبعادها `800x400` بكسل وحجم `150KB` للصورة الواحدة لضمان سرعة تحميل البوابة على الهواتف المتصلة بإشارة واي فاي ضعيفة.
4. **تأكيد وجود وسم الرأس:**
   - لا تحذف `<meta name="viewport" content="width=device-width, initial-scale=1.0" />` من أي ملف، فبدونه ستظهر البوابة صغيرة جداً على هواتف آيفون وأندرويد.
